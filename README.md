# SCATTER!

서로 다른 날의 기록을 연결해 새로운 아이디어를 만드는 로컬 메모 웹. 기존 Figma의 화이트·핑크·라임, 폰트, 캔버스·아카이브 카드 스타일을 유지합니다.

**배포 웹사이트:** https://jiyeonwon.github.io/scatter/

## 실행

이 `SCATTER!` 폴더에서 `npm run dev`를 실행하고 http://127.0.0.1:5173 에 접속합니다. 서버를 실행한 터미널을 열어 두세요. 외부 패키지 설치나 API 키가 필요하지 않습니다. Node.js 기본 HTTP 서버를 사용합니다.

## 시연 흐름

1. **01 HOME**: 원래의 큰 메모 입력창에서 새 기록을 작성합니다. 저장한 메모 목록을 펼쳐 최대 4개까지 함께 선택할 수 있습니다.
2. **02 SCATTER**: 선택한 메모 4개에서 의미 연결이 확인된 실제 토큰만 표시합니다. 원문의 조사, 토큰 ID, 위치, 메모 ID를 보존합니다.
3. **FIND A CONNECTION ↗**: 아무 단어도 선택하지 않았다면 아직 보지 않은 조합을 찾고 아이디어를 만듭니다. 단어를 탭하면 원본 제목·날짜, 원문 열기, 최대 3개의 의미 후보를 확인합니다. 후보 확정 시 핑크 연결선과 spring 이동을 적용하고, 가능한 조합이면 아이디어를 생성합니다.
4. **SAVE TO ARCHIVE**: FIND A CONNECTION이 만든 2~4개 키워드 아이디어와 원문 스냅샷을 저장합니다. 화면 하단의 별도 아이디어 패널 없이 기존 DROP HERE 흐름을 사용합니다.
5. **03 ARCHIVE**: ALL / IDEAS / MEMOS로 원본과 생성 아이디어를 열람합니다. 상세에서 출처별 사용 단어를 확인하고, RE-CUT으로 아이디어를 새 원본 메모로 만듭니다.

단어 탭은 선택/해제, 드래그는 이동, 연결 그룹의 드래그는 함께 이동입니다. DROP HERE에서 순서 변경·개별 제거가 가능합니다. REMOVE ALL은 조합만 비웁니다. 원본 삭제는 HOME/원본 상세에서 확인 후 실행합니다. 캔버스와 현재 조합에서도 제외하되, 이미 저장한 아카이브의 스냅샷은 유지합니다.

키보드: Enter/Space 선택, 방향키 이동, I 원문, G 의미 추천, Esc 연결 해제. 조합 영역의 방향키는 순서 변경, Delete/Backspace는 제거입니다.

## 의미·아이디어 생성 방식

**AI 모델이나 외부 API를 사용하지 않습니다.** 로컬 개념 관계와 원문 문맥, 실제 키워드 조합 규칙을 사용합니다. 좌표·배열 순서·무작위 문장으로 추천하지 않습니다.

연결 규칙은 12종을 유지하며, 현재 10개 초기 기록에서 사용할 수 있는 조합과 이후 사용자가 추가한 메모를 대상으로 동작합니다.

| 연결 방향 | 아이디어 |
| --- | --- |
| 영수증 + 사진/기억/시간 | 하루를 보관하는 영수증 |
| 지하철/지도 + 관계 | 관계의 노선도 |
| 물방울/왜곡 + 기억/감정 | 흐림으로 남기는 감정 |
| 거울/표정 + 기억/관찰 | 나를 관찰하는 거울 |
| 시작/반복 + 변화 | 첫 행동의 작은 변화 |
| 소리/리듬 + 빛 | 소리를 보는 오후 |
| 빛/그림자 + 공간 | 그림자로 읽는 공간 |
| 식물 + 도시/지도 | 도시의 편안한 경로 |
| 촉감/재료 + 종이/디지털 | 손끝으로 접는 화면 |
| 기다림/알림 + 시간 | 기다림의 모양 |
| 책/흔적 + 기억 | 앞선 사람의 흔적 |
| 질문 + 설명문/관찰 | 질문으로 들어가는 전시 |

각 방향에 두 가지 실행안이 있으며, 선택한 실제 키워드를 포함한 3문장으로 생성합니다. 서로 다른 두 개 이상 원본과 올바른 토큰 ID를 검증합니다. 신규 메모도 같은 개념에 해당하면 추천·생성에 참여합니다. 관련 없는 조합·미등록 주제·원본 하나만 선택한 경우 생성하지 않습니다. 범용 언어 모델이 아니므로 다의어·은유와 새로운 주제에 한계가 있습니다.

## 최초 데이터와 저장

localStorage `scatter.v1`을 유지하고 `libraryVersion`으로 초기 등록을 한 번만 수행합니다. 삭제한 초기 메모는 새로고침해도 다시 생기지 않습니다. 모두 삭제한 상태도 유지됩니다.

빈 저장소에서는 정확히 10개입니다. 버전 1의 샘플 20개는 새 구성 10개로 갱신하되 사용자 메모와 아카이브는 보존합니다. 사용자 기록이 있으면 총 개수는 10개보다 많을 수 있습니다. 메모/원본 선택/조합/아이디어 초안/생성 이력/아카이브를 저장합니다. 좌표와 연결선은 화면 세션 상태입니다.

브라우저와 origin별 데이터가 분리되므로 localhost와 127.0.0.1은 다른 저장소입니다. 저장소를 삭제하면 데이터도 삭제됩니다. 개인정보 보호 창은 모두 닫으면 데이터가 사라질 수 있습니다. UUID는 내부 처리에만 사용하며 사용자 텍스트에는 노출하지 않습니다.

## 구조

- `src/seed.js`: 날짜별 초기 기록 10개와 기존 샘플을 안전하게 갱신하는 마이그레이션
- `src/storage.js`: 기존 데이터 호환, 키워드 추출, 원본 삭제, 출처 스냅샷
- `src/connections.js`: 의미 관계 추천
- `src/ideas.js`: 다중 원본 검증과 12종 아이디어 규칙
- `src/app.js`: HOME·SCATTER·ARCHIVE 흐름
- `src/physics.js`: 포인터, 관성, 충돌, 연결선, 묶음 드래그
- `src/styles.css`, `design-tokens.css`, `DESIGN_SYSTEM.md`: 기존 디자인 및 기능 확장
- `assets/`: 기존 로컬 폰트와 Figma SVG
- `tests/`: 저장/초기화/추천/생성/물리 동작 검증

기존 `sketch.js`와 `.gitignore`를 보존했습니다. `.gitignore`의 원래 `*.html`, `*.js` 규칙 때문에 Git 제출 시 규칙 검토 또는 명시적 파일 추가가 필요합니다.

## 검증 범위

`npm test`: 24개 자동 테스트. 초기 10개, 버전 1 마이그레이션, 중복·재생성 방지, 기존 데이터 보존, 토큰 출처, 2~4개 아이디어 조합, 신규 메모 연결, 원본 삭제 후 아카이브 유지, 드롭과 포인터 취소를 검증합니다.

이번 변경에서 Safari 수동 확인: 원래 HOME 입력 레이아웃, SELECTED MEMOS 4개, 연결 가능한 실제 토큰 8개, NEW IDEA 패널 및 기술 문구 제거를 확인했습니다.

12종 전체 생성과 삭제 후 새로고침은 자동 테스트로 검증했으며, 실제 브라우저에서 12종 연속 생성이나 삭제 확정까지 완료했다고 주장하지 않습니다. 이번 버전의 실제 휴대폰 터치 및 브라우저 콘솔 전체 검수도 별도 확인이 필요합니다. 기존 Pointer Events·반응형·reduced-motion 지원은 유지합니다.

추가 수동 확인: 새 메모를 작성한 뒤 SELECTED MEMOS 21 및 실제 ‘조명과’ / ‘공간을’ 토큰 표시를 확인했고, 새로고침 후에도 21개를 유지했습니다. ARCHIVE 상세에서 생성 문장과 각 원본의 날짜·본문·사용 단어가 보존되는 것도 확인했습니다.
